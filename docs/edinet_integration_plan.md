# EDINET連携の実現可能性メモ（2026-04-23）

## 結論（先に要点）

- **実現可能**。EDINET API v2で「日次の提出書類一覧取得」→「財務書類抽出」までは、現行アーキテクチャに無理なく追加可能。
- 現段階では、`edinet-scan` コマンドで **対象日の財務系書類（CSV取得可能）件数を抽出**するPoCを追加。
- 本命は、以下の2層構成：
  1. テクニカル指標（既存）
  2. 財務健全性・成長性（EDINET由来）
  3. それらを **LLMが統合評価** して最終通知判断

## EDINET APIで取れるもの（今回確認）

- `documents.json` で提出書類一覧を取得可能（v2）。
- `documents/{docID}?type=5` でXBRL由来CSV取得が可能（CSV有無フラグあり）。
- 日付指定で取得し、`docTypeCode` により有報/四半期等をフィルタ可能。

> 参考仕様: 金融庁 EDINET API仕様書（v2）

## 現行実装に対する適用イメージ

### Step 1: 収集

- 毎日（または週次）でEDINET提出一覧を収集。
- `docTypeCode` を財務系（例: 120/130/140）に絞る。
- `csvFlag=1` かつ `secCode` ありを優先（上場銘柄との突合が簡単）。

### Step 2: 正規化

- 銘柄キーを `secCode -> ticker(XXXX.T)` に正規化。
- まずは取得可否・提出時刻・docIDなどメタデータ保存。
- 次フェーズでPL/BS/CF主要項目を抽出し、年度/四半期テーブルに保管。

### Step 3: スコア統合

- 既存スコア（Trend/Dip/Breakout）をそのまま維持。
- 財務スコア（例: 売上成長、営業CF、自己資本比率、有利子負債倍率）を追加。
- LLMには「生データ」ではなく、**正規化済み特徴量 + 根拠リンク(docID)** を渡す。

## LLM統合に関する方針

- おっしゃる通り、テクニカルは1材料に留めるのが自然。
- ただし、初期は以下を推奨:
  - ルールで最低限のガード（例: 財務悪化銘柄は除外）
  - LLMは「総合コメント生成 + 最終ランク付け」に使う
- 理由: 完全にLLM任せにすると再現性・デバッグ性が落ちるため。
